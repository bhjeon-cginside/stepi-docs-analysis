결론

rhwp를 이용해 HWP/HWPX 문서의 포맷, 파일 크기, 구역, 최상위 본문 문단, 추출 문자 수와 재조판 페이지 수를 일괄 조사할 수 있습니다. 이번 분석은 1,357개 중 1,355개에 성공해 99.85%의 처리율을 확인했습니다.

페이지 수 주의: pageCount는 한컴 문서에 저장된 공식 페이지 값을 읽은 것이 아니라 rhwp 레이아웃 엔진이 다시 조판한 추정값입니다. 작업량 산정에는 사용할 수 있지만 공식 발간 페이지 수로 단정하지 않습니다.

페이지 수 교차 점검

원본 corpus에서 같은 폴더에 같은 stem의 PDF가 있는 HWP 125쌍을 참고 비교했습니다.

  • 페이지 수 완전 일치: 71/125 (56.8%)
  • 차이 1페이지 이내: 99/125 (79.2%)
  • 중앙 절대 차이: 0페이지
  • 최대 절대 차이: 158페이지

대응 PDF가 HWP와 정확히 같은 저장 시점·내용이라는 보장은 없으므로 이 비교는 정답 데이터셋이 아닙니다. 다만 폰트 대체, 표·도형·다단 조판 및 HWP 3 호환성에 따라 큰 차이가 날 수 있음을 보여줍니다. 정확한 발간 페이지는 대응 PDF 페이지 수 또는 한컴 렌더링 결과를 우선합니다.

실패 및 fallback

  1. 불완전한 HWP 3 스트림 1개: failed to fill whole buffer
  2. 지원하지 않는 암호화 방식 HWP 5 문서 1개

실패 문서는 CSV의 error와 exitClass에 남겼습니다. 이 문서들은 파일 크기만 사용하고, 필요하면 한컴에서 열어 PDF/HWPX로 재저장하는 복구 대상으로 분리합니다.

권장 활용 방식

  1. 작업량 산정은 추출 문자 수와 파일 크기를 우선합니다.
  2. 페이지 수에는 page_count_method=rhwp_reflow_estimate를 함께 기록합니다.
  3. 정확한 페이지 수가 필요한 문서는 대응 PDF를 우선합니다.
  4. 암호화·손상 문서는 자동 fallback lane으로 보냅니다.
